# 公网部署安全指南（frp / 反向代理）

WebUI 能执行服务器命令、安装插件、修改配置，**谁能登录 WebUI，谁就等于拿到了这台服务器**。
通过 frp 等内网穿透暴露到公网之前，请按本文配置。

## 一、推荐拓扑

```
浏览器 ──HTTPS──▶ frps（公网） ──▶ frpc（与 MCDR 同机） ──HTTP──▶ WebUI 127.0.0.1:8000
```

1. WebUI 只监听本机：`config/guguwebui/config.json` 中 `"host": "127.0.0.1"`，
   外部只能经 frp 访问。
2. frp 使用 **`http` / `https` 类型**（按域名转发），不要用 `tcp` 类型（原因见第三节）。
3. 配置 `trusted_proxies`，让 WebUI 识别访客真实 IP（登录限流依赖它）。
4. 每个管理员账号**启用两步验证**。
5. 关闭 QQ 扫码登录（见第五节）。

## 二、frp 配置示例

### HTTPS（推荐）

由 frpc 的 `https2http` 插件终止 TLS，再以 HTTP 转给 WebUI。证书可用 Let's Encrypt 等签发。

`frps.toml`（公网服务器）：

```toml
bindPort = 7000
vhostHTTPSPort = 443
auth.token = "换成足够长的随机字符串"
```

`frpc.toml`（与 MCDR 同机）：

```toml
serverAddr = "frps 的公网地址"
serverPort = 7000
auth.token = "与 frps 相同"

[[proxies]]
name = "webui"
type = "https"
customDomains = ["mc.example.com"]

[proxies.plugin]
type = "https2http"
localAddr = "127.0.0.1:8000"
crtPath = "./fullchain.pem"
keyPath = "./privkey.pem"
```

### HTTP（仅测试用，账号密码会明文传输）

```toml
# frps.toml 增加
vhostHTTPPort = 80

# frpc.toml
[[proxies]]
name = "webui"
type = "http"
localIP = "127.0.0.1"
localPort = 8000
customDomains = ["mc.example.com"]
```

### WebUI 配置

以上两种方式，frpc 都从本机 `127.0.0.1` 连入 WebUI，并在 `X-Forwarded-For` 中追加访客真实 IP。
在 `config/guguwebui/config.json`（或 WebUI「设置 → 安全设置」）中填写：

```json
{
    "host": "127.0.0.1",
    "trusted_proxies": ["127.0.0.1", "::1"],
    "qq_qr_login_enabled": false
}
```

> 不要使用 `hostHeaderRewrite` 改写 Host；如果反向代理（如 nginx 未设置
> `proxy_set_header Host $host`）改写了 Host，导致页面上的保存/登录提示
> “请求来源不受信任”，请把对外地址加入 `allowed_origins`，如
> `["https://mc.example.com"]`。

## 三、`trusted_proxies` 怎么填

WebUI 按 IP 限制登录失败次数（同一 IP + 账号 5 分钟 5 次，同一 IP 20 次）。经过代理后，
WebUI 看到的 TCP 对端都是代理自己（frpc 为 `127.0.0.1`），真实 IP 只能从代理写入的
`X-Forwarded-For` 读取，而这个请求头**访客自己也能伪造**。所以：

| 访问方式 | `trusted_proxies` | 效果 |
| --- | --- | --- |
| frp `http` / `https`（`https2http`） | `["127.0.0.1", "::1"]` | 识别真实 IP；访客伪造的 `X-Forwarded-For` 被忽略 |
| nginx / Caddy 等反向代理 | 代理所在地址 | 同上（代理需追加 `X-Forwarded-For`，nginx 用 `$proxy_add_x_forwarded_for`） |
| frp `tcp` 类型 | **留空 `[]`** | 所有访客都显示为 `127.0.0.1` |
| 局域网直连、不经代理 | 留空 `[]` | 使用真实对端地址 |

**frp `tcp` 类型绝不能填 `127.0.0.1`。** tcp 类型不会写入任何转发头，填了之后 WebUI 会
直接采信访客自带的 `X-Forwarded-For`，攻击者每次换一个“IP”即可无限次猜密码。
留空时伪造无效，但所有访客共用一个 IP 计数：攻击者可以把登录暂时锁住（锁 5 分钟），却无法绕过。
这就是推荐 `http` / `https` 类型的原因。frp 的 `transport.proxyProtocolVersion` WebUI 不支持，请勿开启。

> 旧版本 WebUI 让 uvicorn 按默认规则信任来自 `127.0.0.1` 的 `X-Forwarded-For`，
> 经 frp tcp 隧道访问时任何人都能伪造来源 IP。新版本已改为只由 `trusted_proxies` 决定。

## 四、两步验证（TOTP）

在 WebUI「设置 → 两步验证」中为**当前登录账号**绑定验证器 App（Google Authenticator、
Microsoft Authenticator、1Password 等）：输入当前密码 → 扫码 → 输入 6 位验证码确认。

- 启用后，**账号密码登录**和 **QQ 扫码登录**都需要再输入验证码；
- 启用时会注销该账号在其它设备上的登录；
- 临时登录码（`!!webui temp`）由控制台签发，不要求验证码；
- 验证码只能使用一次；同一账号 15 分钟内输错 10 次会暂停验证码登录；
- **验证器丢失**：在 MCDR 控制台执行 `!!webui 2fa reset <账号>`，会解除绑定并注销该账号全部会话。

每个管理员都需要用自己的账号登录后分别设置。

## 五、QQ 扫码登录的风险

扫码登录使用的是 QQ 小程序开发者工具的授权码，手机上的确认页面**不会显示是哪个网站在请求登录**。
攻击者可以自己生成一个二维码，诱导管理员扫码（例如伪装成“加群”“领奖励”），从而以管理员身份登录。
新版本已把扫码 code 绑定到发起它的浏览器，其它网站拿到的 code 无法在本站兑换。但如果攻击者是在
本站页面上生成二维码再发给管理员，这种钓鱼仍然防不住。

暴露到公网时建议设置 `"qq_qr_login_enabled": false`。如果需要保留扫码登录，请为账号启用两步验证，
这样扫码之后仍需输入验证码。

## 六、其它建议

- **密码**：新建 / 修改的 WebUI 密码至少 8 位。修改密码（控制台 `!!webui change`
  或 GUGUBot `#webui 设置密码`）会注销该账号的全部会话。
- **怀疑 cookie 泄露**：控制台执行 `!!webui logout <账号>` 注销该账号全部会话。
- **只有一个管理员时**：开启「禁用管理员网页登录」（`disable_other_admin`），
  只允许 `super_admin_account` 登录。
- **fastapi_mcdr 挂载模式**：此时 Web 服务由 fastapi_mcdr 启动，WebUI 无法关闭它的转发头处理。
  公网部署请开启 `force_standalone` 使用独立服务。
- **frps**：务必设置 `auth.token`，不要把 frps 管理面板（dashboard）暴露到公网。
- **更隐蔽的方案**：只给自己用时，可以用 frp 的 `stcp` / `xtcp`（访问者端也运行 frpc 并持有密钥），
  WebUI 完全不出现在公网上（`trusted_proxies` 同 tcp 类型，留空）。

## 七、本版本新增的防护（便于审计核对）

| 项 | 说明 |
| --- | --- |
| 真实 IP | 只采信 `trusted_proxies` 的转发头；独立运行时 uvicorn `proxy_headers=False` |
| 两步验证 | TOTP（RFC 6238），密码与扫码登录均生效；票据 5 分钟 / 5 次；验证码防重放 |
| 扫码登录 | code 绑定浏览器会话；可关闭；`start` 每 IP 5 分钟 10 次 |
| 跨站请求 | 写请求校验 `Origin`（应对 frp 共享父域名下“同站不同源”的兄弟子域名） |
| Cookie | HTTPS 下 `Secure`；`HttpOnly`；`SameSite=Lax` |
| 响应头 | `X-Frame-Options: SAMEORIGIN`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: same-origin` |
| API 文档 | `/docs`、`/redoc`、`/openapi.json` 需登录 |
| 账号枚举 | 不存在的账号同样做一次哈希校验；密码正确后才判断“仅超级管理员” |
| 暴力破解 | 临时码全站 5 分钟 100 次失败上限；聊天页验证码查询计入失败次数、生成接口限频 |
| 子服令牌 | `X-Panel-Token` 常量时间比较；主服转发时不携带浏览器 Origin/Cookie |
